# Cloud File Storage

Cloud File Storage — REST API для облачного хранения файлов, разработанный на Java и Spring Boot.

Пользователь может зарегистрироваться, войти в аккаунт, загружать и скачивать файлы, создавать директории, просматривать их содержимое, искать, перемещать, переименовывать и удалять ресурсы.

Файлы пользователей изолированы друг от друга и хранятся в объектном хранилище MinIO.

## Известные недочёты

### Скачивание директорий

Скачивание директорий в формате ZIP пока не реализовано. Приложение умеет скачивать отдельные файлы, но не может собрать содержимое выбранной директории в один архив.

### Перемещение директорий

Объекты внутри директории перемещаются последовательно: каждый объект сначала копируется по новому пути, а затем удаляется со старого. Если во время операции произойдёт ошибка, часть объектов уже будет перемещена, а остальные останутся на прежнем месте. Из-за отсутствия транзакций в S3 такую операцию необходимо выполнять с предварительной проверкой всех исходных и целевых путей, а при ошибке отменять уже выполненные изменения.

### Массовая загрузка файлов

При загрузке нескольких файлов они сохраняются последовательно. Если один из файлов вызовет ошибку, ранее загруженные файлы останутся в MinIO, хотя весь запрос завершится неуспешно. Перед загрузкой необходимо проверять весь набор файлов и возможные конфликты, а при ошибке удалять объекты, загруженные в рамках этого запроса.

### Формирование корневой директории пользователя

Корневая директория пользователя в MinIO формируется на основе имени пользователя. По техническому заданию для этого должен использоваться идентификатор пользователя из базы данных. Идентификатор является более надёжной основой для пути, поскольку он уникален и не меняется вместе с пользовательскими данными.

## Возможности

### Аутентификация

* регистрация пользователей;
* вход в аккаунт;
* выход из аккаунта;
* хранение паролей в зашифрованном виде;
* аутентификация через HTTP-сессию;
* хранение сессий в Redis;
* получение информации о текущем пользователе;
* защита API-эндпоинтов через Spring Security.

После успешной регистрации или входа сервер создаёт cookie `SESSION`.

### Работа с файлами

* загрузка одного или нескольких файлов;
* загрузка файлов во вложенные директории;
* скачивание файлов;
* получение информации о ресурсе;
* перемещение файлов;
* переименование файлов;
* удаление файлов;
* защита от перезаписи существующего ресурса;
* ограничение размера одного файла до 2 GB;
* ограничение размера одного запроса до 5 GB.

### Работа с директориями

* создание директорий;
* создание вложенных директорий;
* просмотр содержимого директории;
* перемещение директорий;
* переименование директорий;
* рекурсивное удаление директорий вместе с содержимым.

Путь директории должен заканчиваться символом `/`.

Пример:

```text
documents/
documents/photos/
documents/photos/2026/
```

### Поиск

Приложение позволяет искать файлы и директории по части названия.

Поиск выполняется только среди ресурсов текущего пользователя и не зависит от регистра символов.

### Изоляция пользовательских файлов

Каждый пользователь работает только со своими файлами.

В MinIO для пользователя создаётся отдельное пространство имён:

```text
user-{username}-files/
```

Например:

```text
user-kamil-files/documents/report.pdf
user-alex-files/photos/avatar.png
```

В API внутренний префикс не отображается. Пользователь видит только относительный путь:

```text
documents/report.pdf
```

### Валидация и обработка ошибок

Приложение проверяет входные данные и возвращает понятные HTTP-ответы:

* `400 Bad Request` — ошибка валидации или некорректный путь;
* `401 Unauthorized` — пользователь не авторизован или указаны неверные данные;
* `404 Not Found` — ресурс не найден;
* `409 Conflict` — пользователь или ресурс уже существует;
* `500 Internal Server Error` — ошибка хранилища или внутренняя ошибка приложения.

Пример ответа с ошибкой:

```json
{
  "code": 409,
  "message": "ресурс уже существует"
}
```

### Controller

Контроллеры принимают HTTP-запросы и возвращают ответы в формате JSON.

Отдельные контроллеры отвечают за:

* регистрацию и аутентификацию;
* получение текущего пользователя;
* работу с файлами;
* работу с директориями.

### Service

Сервисный слой содержит основную бизнес-логику приложения:

* регистрацию пользователей;
* загрузку и скачивание файлов;
* создание директорий;
* получение информации о ресурсах;
* поиск файлов и директорий;
* перемещение и переименование;
* удаление ресурсов;
* преобразование пользовательских путей во внутренние пути MinIO.

### Repository

Repository-слой отвечает за работу с PostgreSQL через Spring Data JPA.

В PostgreSQL хранятся пользователи:

```text
User
├── id
├── username
└── passwordHash
```

Изменения структуры базы данных выполняются через Flyway.

Миграции расположены в:

```text
src/main/resources/db/migration
```

### Storage

Работа с MinIO вынесена в отдельный слой хранения.

Приложение использует MinIO для:

* загрузки объектов;
* скачивания объектов;
* получения метаданных;
* создания директорий;
* получения содержимого директорий;
* поиска ресурсов;
* копирования и перемещения объектов;
* удаления файлов и директорий.

Схема выполнения запроса:

```text
HTTP Request
      |
      v
Controller
      |
      v
Service
      |
      v
MinioStorage
      |
      v
MinIO
```

## Аутентификация и сессии

Для аутентификации используется Spring Security.

После успешной регистрации или входа:

1. сервер проверяет логин и пароль;
2. создаётся `SecurityContext`;
3. создаётся HTTP-сессия;
4. сессия сохраняется в Redis;
5. клиент получает cookie `SESSION`;
6. браузер отправляет cookie при следующих запросах;
7. Spring Security определяет текущего пользователя.

Схема:

```text
Client
   |
   | Cookie: SESSION
   v
Spring Security
   |
   v
Spring Session
   |
   v
Redis
```

Пароли пользователей не хранятся в открытом виде. Перед сохранением они кодируются с помощью `PasswordEncoder`.

## REST API

Все эндпоинты, кроме регистрации, входа и Swagger UI, требуют авторизации.

### Аутентификация

| Метод | Эндпоинт | Описание |
|---|---|---|
| `POST` | `/auth/sign-up` | Регистрация пользователя |
| `POST` | `/auth/sign-in` | Вход в аккаунт |
| `POST` | `/auth/sign-out` | Выход из аккаунта |
| `GET` | `/user/me` | Получение текущего пользователя |


Требования к имени пользователя:

* длина от 3 до 10 символов;
* латинские буквы;
* цифры;
* символы `@` и `.`.

### Сессии в Redis

Приложение использует серверные HTTP-сессии вместо JWT.

Redis позволяет хранить сессии отдельно от экземпляра приложения и поддерживать авторизацию при горизонтальном масштабировании.

### Flyway для управления базой данных

Структура PostgreSQL управляется миграциями Flyway.

При запуске приложения новые миграции применяются автоматически.

### Потоковое скачивание

Файл передаётся клиенту через `StreamingResponseBody`.

Это позволяет не загружать весь файл целиком в оперативную память приложения перед отправкой.

### Dependency Injection

Контроллеры, сервисы, репозитории и компоненты хранилища связаны через Dependency Injection.

Это уменьшает связанность компонентов и упрощает тестирование приложения.
